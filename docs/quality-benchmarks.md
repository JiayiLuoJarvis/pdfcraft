## 一、 姿态与定位

遵循 [`AGENTS.md`](../AGENTS.md)「现阶段姿态」：**当前处于 0.x 初期，无生产包袱，不背历史技术债**。

任何架构设计、模块分层、错误面与 API 边界，优先选择长期正确的形状，不为了「少写代码」或「容易实现」而留下妥协的中间形态。本文确立各包在 Rust 开源生态中对标的最高水准库及其核心工程要素。

## 二、 全局唯一总标杆：`typst`

作为同样基于 Rust 实现的现代文档与矢量排版系统，[Typst](https://github.com/typst/typst) 是整个 `pdfcraft` 项目在架构设计与工程交付上的**全局总标杆**。

### 1. 纯粹的不可变几何帧（Frame）架构
- **排版计算是纯函数**：排版流水线严格单向流动：
  $$\text{DocumentSpec} \longrightarrow \text{Layout 约束求解} \longrightarrow \text{不可变纯几何 Frame} \longrightarrow \text{Canvas / Backend 渲染}$$
- **渲染零决策**：底层渲染后端（krilla 适配器）只负责将最终确定的纯几何与字体指令翻译为 PDF 操作符，不参与、不反推任何排版决策。

### 2. 位级确定性（Bit-for-bit Determinism）
- 在相同的文档输入和字体资源下，排版计算输出的坐标序列与矢量指令必须严格确定，消除一切由浮点误差累积、全局状态或执行环境带来的非确定性。

### 3. 基于几何快照的自动化测试网格
- 测试排版不依赖肉眼比对渲染出的二进制 PDF，而是对排版输出的不可变 Frame / 录制指令流进行结构化文本快照比对（Snapshot Testing），保证重构与性能调优时排版行为不漂移。

## 三、 四个独立包的垂直极致标杆

各 crate 职责与物理特性不同，在实现深度上分别对标对应领域的顶尖 Rust 开源项目：

```
┌────────────────────────────────────────────────────────────────────────┐
│                        pdfcraft Workspace                              │
├───────────────────┬───────────────────┬────────────────────────────────┤
│ Crate             │ 核心物理性质      │ 垂直极致标杆                   │
├───────────────────┼───────────────────┼────────────────────────────────┤
│ pdfcraft-pdf      │ 流式排版与分页    │ typst-layout                   │
│ pdfcraft-forms    │ 表单压平与字形子集│ google/fontations (read-fonts) │
│ pdfcraft-orgchart │ 层次图论与排版    │ petgraph + typst 矢量图层      │
│ pdfcraft-post     │ 字节管道与加密    │ rustls (Sans-I/O + Typestate)  │
└───────────────────┴───────────────────┴────────────────────────────────┘
```

### 1. `pdfcraft-pdf` ── 对标 `typst-layout` / `typst-render`
*   **定位**：流式正文、表格、断行、跨页截断与页眉页脚排版引擎。
*   **极致标准**：
    *   **严格单向无环的模块 DAG**：`geom -> error -> limits -> fonts -> canvas -> text -> layout -> spec`。严禁任何反向依赖与内部循环。
    *   **测量与绘制同一管线**：字符映射（charmap）、宽度测量（skrifa 0.48.0）与最终字形绘制使用同一组 Glyph ID，不靠渲染后端反推测量值。
    *   **私有适配器彻底封装**：上层排版代码只感知抽象 `Canvas`，所有 krilla 类型与依赖死死锁在 `backend` 私有模块中，不向外泄漏一丝一毫。

### 2. `pdfcraft-forms` ── 对标 `google/fontations` (`read-fonts` / `skrifa`)
*   **定位**：读取已有 AcroForm、TrueType `glyf` 子集化、TTC 拆面与表单压平（Flatten）。
*   **极致标准**：
    *   **零拷贝视图类型与严密边界**：对底层二进制字体表及 PDF 对象树的处理，全面采用带有生命周期绑定的切片视图抽象。所有偏移（offset）与长度读取均具备形式化前置检查。
    *   **绝对输入防御**：面对格式损坏、畸形或恶意构造的 PDF 表单与字体字节，永远返回精确的结构化错误，**坚决不 panic、坚决不发生内存越界**。
    *   **纯安全内存组装**：子集化生成的 TTF 表使用可验证的二进制序列化器组装，杜绝指针与裸内存操作。

### 3. `pdfcraft-orgchart` ── 对标 `petgraph` + 紧凑分层图布局算法
*   **定位**：股权架构与对外投资图的自动布局与矢量渲染。
*   **极致标准**：
    *   **拓扑结构与几何渲染完全正交**：图的拓扑模型（节点分支、持股比例、合并汇聚关系）是纯净的抽象图数据结构，不耦合任何排版坐标与字号逻辑。
    *   **纯数学布局计算**：分层布局算法以拓扑图和测量引擎作为纯输入，计算出紧凑且无重叠的几何位置树，中间不产生绘制副作用。

### 4. `pdfcraft-post` ── 对标 `rustls` (Sans-I/O & Typestate) + `oxipng`
*   **定位**：已有 PDF 字节流的后处理（元数据设置、加密、印章、合并与流水线执行）。
*   **极致标准**：
    *   **类型状态模式（Typestate Pattern）**：
        利用 Rust 类型系统在编译期锁定生命周期状态。例如：通过类型签名确保无法对已经加密完成的 PDF 执行盖章或元数据修改，彻底消除运行时状态判断漏洞。
    *   **Sans-I/O 架构**：协议与字节处理只操作内存切片（In-memory buffers），解耦文件系统与外部 I/O，具备极高可测性与高并发吞吐能力。
    *   **防资源耗尽攻击（DoS Defense）**：在流式解压、交叉引用表（XRef）读取与嵌套对象遍历时，强制引入深度与内存配额上限（Limits），拦截解压缩炸弹（Decompression Bomb）与循环递归引用。

## 四、 横切工程规范标杆（BurntSushi 标准）

各包内部代码编写与维护必须贯彻以下通用准则：

1.  **零随意 `unwrap()`**：
    *   业务路径中必须返回强类型 `Result`。
    *   仅在编译器无法推导但数学/逻辑上已形式化证明成立的不变量位置使用 `expect("REASON")`，并在上方注释中详细解释不变式成立的前置条件。
2.  **错误设计结构化与强类型**：
    *   底层 crate 必须使用显式强类型错误枚举（基于 `thiserror`），每个变体必须携带精确且最小的定位上下文（如字节偏移、表名、限制阈值等），拒绝无上下文的字符串错误或粗暴擦除类型。
3.  **防误用的人体工程学（API Ergonomics）**：
    *   遵循 [Rust API Guidelines](https://rust-lang.github.io/api-guidelines/)。
    *   构造函数强制校验有效性（如非负长度、有限浮点数、合法编码），使非法状态在类型系统或构建边界处被即时拦截。
4.  **完备的文档与 Doctest**：
    *   所有公共类型、函数与方法必须包含详尽的文档注释，显式说明参数意图、`# Errors` 以及 `# Panics` 条件。
    *   每个核心公开 API 必须包含可编译运行的文档测试示例（Doctest）。
