# Knife 14 取舍

设计见同目录 `design.md`。这里只记否决掉的做法，以及默认值为什么落在现在这组数上。

## 空白不能伪装成文字

空字符串会被 `Paragraph::append` 和 `cluster_tagged` 丢掉，占不了宽。普通空格会进 cmap，类是 `PairClass::Sp`，行首被删除；放不下的行尾空格还会多出一条空视觉行。全角空格是 `Id`，两侧都能断，并且是真字形。下划线字符同样要测量、要缺字检查，画出的是 glyph fill，不是一条 `Stroke`。

把空白做成新的 `Face` 也不成立。`Face` 是每个字形标量上的标签，测量时要映射到 `FontId`。没有标量就没有标签。

所以行内项是 `Text | Blank` 的和类型。文本仍按原规则合并；空白打断合并。这就是数据形状里的判别联合，不是平行的 `FlowNode`，也不是文字装饰。

`decoration: underline` 划的是已有字形的墨，不预留手写宽度。提案写明填空不是这个功能。本刀不加装饰字段。

## 不把填空做成 `HLine`

块级分隔线已经会发 `FragmentCommand::Stroke`，类型可以复用：`Path::line`、`Paint::solid`、`Stroke::new`。布局语义不能复用。

`HLineNode` 的宽是整框 `W` 或一条 `Positive` 长度，对齐的是框内的规则；高度是 `space_before + thickness + space_after`；分页时整节点移动。填空的宽是定宽或本行剩余宽，x 是行内笔位置，高度不能把线粗算进去，分页只跟着那一行。把填空降成 `FlowNode::HLine` 会失去左右文字，也会把行高撑开。

`HLine` 的 y 是「盒子顶 + 线粗的一半」，原点是规则盒，不是文字基线。填空的路径放在 `baseline + 1pt`。默认线粗 1pt、描边以路径为中心时，墨的上沿大约在基线下 0.5pt，用来避开字形。若把路径放在 `baseline + thickness/2`，1pt 的线会贴上基线。偏移用绝对值 1pt，不随字号缩放；提案给的是「略下方」，当前字号又还没有公开的逐段设置。

线色默认取 `style.color`。今天的默认样式就是黑，所以和「默认黑」在现有调用下画出来一样。一旦样式带上非黑文字色，横线跟着文字，而不是跟 `HLine` 那条独立的黑色。调用方仍可用 `.color(...)` 覆盖。不从 `HLine::default` 拷一套 Center、`space_before`、黑。

## 剩余宽只能在 pack 里算

`width_of` 在打包之前按 cluster 调用，看不到本行已用宽度，也看不到这颗原子最终落在 `W'` 还是 `W`。把 fill 预先做成一个很大的定宽，会在当前行溢出，再在下一行行首被当成不可拆原子报错，横线不会铺满。把 fill 做成 BK 会先提交当前行，再占满下一行，当前行行尾反而空着。

接纳 fill 时宽度取 `avail - line_width`，并把 `line_width` 设为 `avail`。行宽含这截宽度之后，Center / End 的 `align_x` 才是 0；若只在绘制时把线补进空隙，对齐会把文字挪走，线仍停在旧坐标上。

剩余宽为 0 时省略 stroke、行宽保持为预算、不新起一行。顶满的一行再写 `blank_to_end()` 是「没有可铺的剩余」，不是几何非法。`Path::line` 虽然接受重合端点，放置阶段直接不发命令，避免和 `Layer::line` 的零长度错误缠在一起。定宽 0 用同一条省略规则：`Length<NonNegative>` 允许 0，线粗才是 `Positive`。0 宽不右移后文。若定宽改成 `Positive`，调用方就无法表示「占位但暂不画线」，也会和 §2.0 里「不能为负」的量分叉。

吃到行尾只作用于它落下去的那一条视觉行，不在后面每一行重复。前面的文字该怎么折还怎么折。

## 行片段，而不是一条 glyph_range

测量后的字形带没有空洞。`金额` 和 `元` 若只是从 tape 里抽掉空白，两侧字形下标相邻，`glyph_runs_for_line` 会把它们接成一条连续 advance。`BrokenLine` 今天只留下一个半开 glyph 区间和总宽。总宽能藏住一个缝的大小，藏不住缝在区间里的位置，更藏不住两处缝。

断行在 `emit` 时写出有序片段：连续 `Ink` 一段，空白一段。放置时先画左段，`x` 加上空白宽，再画右段。右段 `GlyphRun.origin.x` 因此包含空白。空白宽度为 0 时也切开两段 run，这样「有没有发 stroke」和「笔有没有经过这颗原子」是两件事；0 宽时两段的 x 相接，没有 `StrokePath`。

fill 的解析宽度诞生在 `pack` 里，所以必须由断行结果带出来。段落侧若只记「第 i 颗空白宽多少」，仍然不知道它落在哪一行、位于哪些字形之间。

空白把文本切成组，每组自己 `cluster_tagged`。没有空白时全段仍是一组，CRLF 跨 `Face` 的折叠不变。空白两侧若拼成一条标量流再折叠，`\r` 和 `\n` 会吞掉中间这颗空白的位置。

`Atom::Hard` 保存 cluster 下标。否则 `eof_cursor` 在「空白原子插在 BK 前」时会把原子下标当成 cluster 下标。纯文本路径上两者仍然相等，旧测试不用改期望。

## 断在空白之前，pair 表只对文字生效

定宽空白不使用任何 `PairClass`。`Sp` 会在行首消失。现有六类里没有「行首保留、不查 cmap、前面总是可以断开」的一类。给表加一行会碰到 `Op` 整行禁止断开，空白就粘在开括号上，剩余宽不够时整段报 `UnbreakableWiderThanFrame`，不能整颗移到下一行。

采用的规则：空白之前总是断点，放不下就整颗下移；空白不拆开。空白之后看同一行里它左边那颗字和右边那颗字的 pair 表，空白本身透明。这样 `字。` 那种「闭标点不单独掉下去」在空白两侧仍在。空白已经处于行首时，左边的字不在这一行，空白后面允许断开，避免一颗行首空白把后续整段粘成不可拆。

开口括号后的空白因此可以下移，括号留下。这是「不可拆占位」：不可拆的是空白这一颗原子，不是空白加前文。

fill 不参加这次搜索。它的宽度就是剩余宽，接纳它不会溢出。若再允许「为了后面的原子在 fill 前断开」，填空会掉到下一行，当前行行尾留白，和「铺到本行剩余宽」相反。非末尾 fill 在进 `pack` 前已经是 `RunAfterFillBlank`。

溢出比较的是该视觉行的预算。第一条已发出的行是 `W'`，其后是 `W`。行首放不下不会改试 `rest`。这和 `first_line_overflow_reports_the_first_budget`、以及缩进 12、框 24、`"AA"` 报 `avail ≈ 12` 的段落测试是同一条规则。数据形状里写的「宽于当前框 `W`」比这条粗：首行的当前行预算已经是 `W'`。用整框 `W` 做首行比较会让「缩进后放不下、整行却放得下」的空白悄悄成功，文字原子却失败。

错误变体继续用 `UnbreakableWiderThanFrame`。行首空白的 `width` 就是空白 pt，`avail` 是该行预算。不新造「空白太宽」。

## 汉字数在布局期乘字号

`blank_em` 只保存 `u32`。`layout_runs` 里乘 `style.font_size`。`Paragraph` 闭包执行时还没有把 `Style` 交给段落；`Flow::paragraph` 在闭包结束后才克隆样式。现在字号恒为 12pt，两边乘出来一样。以后若样式能改字号，布局期乘到的是真正参与断行的那个数。

在 builder 里提前乘，需要把字号塞进 `Paragraph`，并在样式随后变化时改掉已写入的 pt。没有这种变化今天看不出来，接口会先把「当前字号」钉死在闭包开始时。

`u32` 含 0。`blank_em(0)` 与定宽 0 一样省略 stroke。不用 `NonZeroU32`，否则 0 要另走一条错误。

## 三个方法，而不是一个枚举参数

`blank`、`blank_em`、`blank_to_end` 并排在 `text` / `bold` 旁边。宽度互斥体现在方法上，也体现在内部的 `BlankWidth` 上。一个 `blank(BlankWidth)` 能少一个名字，但吃到行尾和定宽在调用点长得一样，组装期「后面不许再有 run」也不如独立方法显眼。

线粗、颜色、偏移是可选链式设置，默认值可以完全不写。不做成每条空白一个闭包：`hline` 是整块节点，填空是行内项，闭包会把 `text` 与 `blank` 的节奏拆开。句柄只活到语句结束，避免横跨后续 `text` 借用 `Paragraph`。

`RunAfterFillBlank` 单独成变体。组装期能发现，又不是坏的长度，也不是放不下的宽度。塞进 `InvalidGeometry` 会和「缩进大于等于框宽」共用一个错误，测试和调用方都分不清。

## 行高、分页、范围

stroke 写进 `LineBox` 的片段列表，y 只存 `baseline + offset`。`fragment_from_lines` 加上本片段内的 `index * line_height`，与 glyph 相同。尾页从 0 编号，所以不能在第一次布局时把「全文行号」烘进 y。x 和 fill 宽度则必须烘进 `LineBox`：续页的 `ParagraphNode::split` 不再断行。

空的 Body glyph run 留在「这一行没有字形」的行首，包括只有空白的行。否则列表 `first_baseline` 会跳过 stroke，标记 y 对不齐。这不是用下划线 glyph 冒充横线。

单元格与 Band 今天只接收字符串，进的是 `TextNode::new`，调用方写不到 `Paragraph`。Layer 走 `single_line_run`。本刀不加第二条入口。列和列表项已经能调用 `paragraph`，填空自动用它们的框宽。

不合并相邻空白：两条空白可以有不同线粗和颜色。不新增画布命令，不改 krilla 线帽，不测内容流坐标。后端冒烟只看 `%PDF`。
