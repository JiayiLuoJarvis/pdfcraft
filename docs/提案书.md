### 1. 调用方式：Rust 值，流式正文，定位组件作逃逸

已按你的说明定下。`pdfcraft-design.md` 里「公共 API 是一份静态文档定义，可选 serde」这一条作废，以这里为准。调用方不写闭包。公共入口是 `DocumentSpec` 和 `layout_spec`。

你写的是一组 Rust 值。`if`、`for` 就是 Rust 自己的 `if`、`for`，用来根据动态数据决定 `body` 里放哪些块。库不另做模板语言，也不把 JSON 当主接口。

正文是流式布局：行内从左到右，块与块从上到下。库负责换行、换页、表格跨页、页眉页脚。电子章和水印不进这股流，用定位标记按页面坐标贴。

值分两个时刻：

- **组装时。** 合同数据已经在手里。`if kind == A`、`for item in items` 在这里跑，把段落、栏、表放进 `SectionSpec.body`。这一刻还不知道会排成几页。
- **每一页绘制时。** 正文已经分页。页眉、页脚、水印、电子章是 `TextRun` 和 `PageWhen`。库在绘制这一页时填上页码、页数、本节页码，以及是否最后一页。

`if` 不产生一种叫 If 的节点。走哪一支，哪一支里的 `Block` 才会进入正文流。另一支根本不会成为 PDF 里的内容。

同一段组装，`contract.kind` 不同，流里的块就不同。

```rust
let mut body = vec![Block::paragraph(format!("合同 {}", contract.id))];
if contract.kind == Kind::A {
    body.push(Block::paragraph("按甲方案执行。"));
    let mut rows: Vec<TableRow<_>> = Vec::new();
    for item in &contract.items {
        rows.push(TableRow { cells: vec![
            CellSpec { content: vec![CellBlock::Text(item.name.clone())], ..CellSpec::default() },
            CellSpec { content: vec![CellBlock::Text(item.amount.clone())], ..CellSpec::default() },
        ]});
    }
    body.push(Block::Table(TableSpec {
        header: vec![TableRow { cells: vec![
            CellSpec { content: vec![CellBlock::Text("项目".into())], ..CellSpec::default() },
            CellSpec { content: vec![CellBlock::Text("金额".into())], ..CellSpec::default() },
        ]}],
        body: rows,
        ..TableSpec::default()
    }));
} else {
    body.push(Block::paragraph("按乙方案执行。"));
    body.push(Block::paragraph("乙方案没有明细表。"));
}
let rendered = layout_spec(DocumentSpec {
    page_size: PageSize::A4,
    resources,
    limits: Limits::default(),
    info: DocumentInfo::default(),
    sections: vec![SectionSpec { body, ..SectionSpec::default() }],
})?;
```

`kind == A` 且 `items` 有两行时，正文流是三块：

1. 段落「合同 C-18」
2. 段落「按甲方案执行。」
3. 表：项目 / 金额，后面两行数据

`kind == B` 时，正文流是三块，没有表：

1. 段落「合同 C-18」
2. 段落「按乙方案执行。」
3. 段落「乙方案没有明细表。」

页眉页脚和定位标记仍在绘制时填数，见下面的完整模板。

```rust
let rendered = layout_spec(DocumentSpec {
    page_size: PageSize::A4,
    resources,
    limits: Limits::default(),
    info: DocumentInfo::default(),
    sections: vec![SectionSpec {
        header: Some(BandSpec {
            left: Some(BandSlot::Text(vec![TextRun::Literal(company.name.clone())])),
            right: Some(BandSlot::Text(vec![
                TextRun::Literal("第 ".into()),
                TextRun::PageNumber,
                TextRun::Literal(" 页 / 共 ".into()),
                TextRun::PageCount,
                TextRun::Literal(" 页".into()),
            ])),
            ..BandSpec::default()
        }),
        body,
        behind: vec![LayerMark::Text {
            when: PageWhen::All,
            text: vec![TextRun::Literal("草稿".into())],
            at: Point::try_pt(180.0, 400.0)?,
            style: TextStyle::default(),
        }],
        front: vec![LayerMark::Image {
            when: PageWhen::Last,

        }],

    }],

```

`behind` 垫在正文下面，用来做水印。`front` 盖在正文上面，用来贴电子章。`PageWhen::Last` 是绘制时的「只在最后一页」。

Flowable 那套「自己报告高度再自己画」留在库内部，用来实现段落、栏和表的分页。调用方不实现这个 trait。

**文档信息（2026-10-14 已确认）。** `DocumentSpec.info` 的类型是 `DocumentInfo`。字段是 `title`、`author`、`subject`、`keywords`、`language`。`layout_spec` 保存这份值。`to_pdf` 在重放页面前调用已有的 `set_document_info`，再由 emit 写入 PDF 的 `/Info`。空字符串不写。Creator 固定为 `pdfcraft`。不设 Producer，调用方也不能改 Creator 或 Producer。验收命令是 `pdfinfo`。`Title` 与 `Author` 等于所填字符串。这与 §11 `pdfcraft-post` 的 `SetMetadata` 是不同产品：排版生成锁 Creator/Producer；后处理改已有 PDF 时开放二者。

这一条里还剩一个贴法要定：电子章是钉死在页面坐标上（例如每页右下角，或只在最后一页右下角），还是要跟着流走（例如总贴在「签署栏」这段的右边，正文变长时章跟着下移）。水印按页面坐标、垫在字下面，这一点先按你举的例子定了。

### 2. 元素清单（对照 pdfmake，先枚举，未取舍）

当前讨论停在这里。下面是 pdfmake 文档定义里出现过的种类，外加你已经说的电子章，以及常规公文 / 函证场景补列。还没决定第一版封装哪些。

pdfmake 把东西分成三层：正文流里的节点、挂在节点上的属性、整份文档的装饰和设置。属性不是另一种节点。

**正文节点。** 出现在 `content` 里，也可以嵌进栏、单元格、列表项。

| pdfmake / 补列 | 是什么 |
| --- | --- |
| `text` | 文字。整段一段，或一段里混排多种样式。字符串是它的简写 |
| `stack` | 把若干节点从上到下绑成一组。文档的 `content` 数组本身就是一个隐式 stack |
| `columns` | 从左到右分栏，栏内再往下排。栏宽可以是固定值、按内容、按剩余比例 |
| `table` | 表。行、单元格、列宽、行高、重复表头、单元格合并 |
| `ul` | 无序列表。项可以是文字，也可以再嵌列表、表、栏 |
| `ol` | 有序列表。编号样式、起始数字、倒序 |
| `image` | 图片。宽高、放进某个矩形（fit）、铺满（cover） |
| `canvas` | 一块矢量图，里面是矩形、直线、折线、椭圆。跟着流走，不是自由贴到页面上 |
| 分隔线 | 流内水平线（标题下线、落款区分隔、附件前分隔等）。公文常用；封装名待定（如 `hr` / `line`），也可用单行表或 `canvas` 代替，取舍时再定 |
| `svg` | 嵌一段 SVG。**不做独立元素**：需要图走 image；简单矢量走 behind/front path |
| `qr` | 二维码。**不做独立元素**：调用方生成后走 image（或日后 svg）；库不集成生成器 |
| `toc` | 目录。**不做** |
| `section` | pdfmake 0.3 才有。从这里起换纸张、方向、边距、页眉、页脚、水印、背景 |

**挂在节点上的属性。** 段落、表、图片都能带，本身不是元素。

| pdfmake / 补列 | 是什么 |
| --- | --- |
| 样式 | `style`、`bold`、`italics`、`font`、`fontSize`、`color`、`background`、`alignment`、`lineHeight`、`characterSpacing`、`decoration`（下划线、删除线）、`opacity`、`margin`、首行缩进 |
| 首行缩进 | **公文刚需**。正文段落常见约二字缩进；属样式的一部分，不另做节点。具体默认值（字数 / 磅值）以后定 |
| 两端对齐 | **已确认**，见 §12.3 |
| 填空下划线 | 行内「金额：____」「签字：______」一类空白 Underscore，供手写或预留宽度。不只是给已有文字加 `decoration: underline`；封装是行内 run 还是属性，取舍时再定 |
| `link` / `linkToPage` / `linkToDestination` | 点文字跳到网址、某一页、或文内锚点 |
| `pageBreak` | 这个节点之前或之后换页，还可指定奇数页或偶数页 |
| `unbreakable` | 这一组不要从中间拆到两页 |
| `absolutePosition` | 离开正文流，按页面坐标放。电子章用的就是这种 |
| `relativePosition` | 相对「本来该出现的流位置」再偏移 |
| `width` / `height` / `fit` / `cover` | 图片、二维码、部分节点的尺寸 |
| `colSpan` / `rowSpan` | 单元格合并 |
| `headerRows`、`widths`、`heights`、`dontBreakRows` | 表的重复表头、列宽、行高、禁止一行拆开 |
| `tocItem`、`id`、`headlineLevel` | 目录项、锚点、标题级别 |

**文档级。** 不放进 `content` 数组。

| pdfmake | 是什么 |
| --- | --- |
| `header` / `footer` | 页眉页脚。可以是固定内容，也可以按当前页、总页数现算 |
| `background` | 每一页画在正文下面 |
| `watermark` | 每一页的水印，垫在正文下面 |
| `pageSize` / `pageOrientation` / `pageMargins` | 纸张、横竖、边距 |
| `styles` / `defaultStyle` | 具名样式和默认样式 |
| `images` | 图片先起名，正文里再引用 |
| `info` | 标题、作者等文档信息。2026-10-14 已确认，见 §1 `DocumentSpec.info` |
| 加密 | `userPassword`、`ownerPassword`、权限 |

#### 2.1 段落（换行宽已定；其余随 §3）

**换行可用宽度 `W`（已定）。** 段落不按纸张全宽断行，只按**当前所在框**的宽度：

| 段落写在哪 | `W` |
| --- | --- |
| 文档正文流（普通公文） | 页宽 − 左边距 − 右边距。例如 A4、左右边距各 72 pt 时，`W = 595.2756 − 72 − 72` |
| `columns` 某一列里 | **该列列宽**（不是整页正文宽；到列右缘就必须换行） |
| 表格单元格里 | 该格内容宽（列宽减去该格的 padding / 边框占位；细则随表另定） |
| 列表项里 | 该项的内容宽（列表符号占位扣掉之后；细则随列表另定） |

首行缩进只收窄**第一行**的可用宽：`W' = W − indent`；后续行仍用满 `W`。

断行算法（字素簇、分类表）在给定的 `W` 上跑；换页是竖直方向的事，不改变水平 `W`。`behind` / `front` 里按页面坐标贴的字不走这套流式换行。

#### 2.0 公共基础：长度与颜色（独立模块，已定方向）

排版内部与 Canvas **一律用 PDF 点（pt，1/72 英寸）**。调用方书写时不必只写裸 `f32` pt。长度和颜色各自成模块，供段落、填空、分栏、表、页边距这些元素复用。元素讨论里出现的「宽 120」「边距 72」均指**换成 pt 之后**的数。调用方可以用 `mm` 构造长度，进布局前先换成 pt。

**约束优先类型化（已定）。**  
凡能在类型上表达的不变量（非负长度、正字号、有限坐标、合法枚举纸张/方向、非空 URI 若做链接等），**优先用 newtype / 枚举 / 受控构造**在边界处理掉，而不是在 layout 各处分支 `if` 再报 `InvalidGeometry`。这样：

- 调用方在组装期就能发现非法值（或根本组不出非法值），比分页中途失败更友好；
- 热路径少重复校验，排版假设「进来的长度已合法」，有利于性能与推理。

仍允许在组装/lower 边界做一次「跨字段」校验（如 Fixed 列宽之和超过框宽、合并单元格重叠）——那是类型装不下的关系约束，不是「单个 f32 是否为负」这类事。**禁止**用整数 pt（`u32`）牺牲亚点精度来换非负。

**长度**

| 项 | 约定 |
| --- | --- |
| 内部存储 / 测量 / 断行 / 绘制 | 只有 pt（`f32`） |
| 调用方 | 通过长度类型表达，默认单位是 pt；也支持例如 `mm`（以及后续若需要的 `cm` / `in` 等） |
| 非负 / 正数 | 需要「不能为负」的量（spacer 高、margin、线粗等）用 **非负长度 newtype** 在构造期约束；必须 `> 0` 的（字号等）用 **正长度**。**不要用 `u32` 表示 pt**。`NaN`/±∞ 在构造期拒绝 |
| 换算 | 集中在该模块（设计稿已有 `MM_TO_PT = 72/25.4`）；元素代码禁止各自发明一套乘法 |
| 落点 | `geom`（或从 `geom` 再拆的 length 子模块）；具体 API 形状随实现定 |

**规格里的长度（已定）。**  
`DocumentSpec` 里的长度、点和矩形，字段类型是 `Length<_>`、`Point`、`Rect`。调用方先用 geom 构造出合法值，再写入规格。构造函数返回 `Result`，例如 `NonNegative::pt`、`NonNegative::mm`、`Positive::pt`、`Point::try_pt`、`Rect::try_pt`、`Margins::try_uniform`、`Pen::new`。单个非法值在构造时失败。`layout_spec` 也返回 `Result`。调用方的函数若返回本库的 `Result`，就对这些构造使用 `?`。

- 类型化仍在边界内侧成立。layout 热路径只见已合法的 `Length<_>`。
- 长度、点、矩形字段不收未校验的裸 `f32`。`Pen::new` 和 `Margins::try_uniform` 仍通过 `IntoPositive`、`IntoNonNegative` 接收 pt 数值或长度。校验集中在 geom 的 `Into*`、`pt`、`mm`。
- 不靠宏，也不把会 panic 的 `pt` 当主路径。

**颜色**

| 项 | 约定 |
| --- | --- |
| 内部 | 自有 `Color`（如 RGBA），Canvas / 样式 / 描边都用它 |
| 调用方 | 颜色封装也在独立模块（构造、具名色等），不让每个元素自己解析字符串或散落魔法数字 |
| 后端 | 仅 `backend` 把自有 `Color` 译成 krilla；layout 不依赖 krilla 色类型 |
| 范围 | 第一版纯色即可；渐变不在此模块先行展开 |

填空下划线的定宽、线粗、线色，以及页边距、列宽、字号等，都消费上述模块的结果，不在元素里重做单位/颜色语法。

#### 2.2 填空下划线（已定方向）

行内占位，嵌在段落里，与 `text` / `bold` 并列。是**空白宽度 + 其下横线**，不是给已有文字加 `decoration: underline`。

**两种宽度（都要）**

| 形态 | 含义 |
| --- | --- |
| 定宽 | 调用方给长度（经 §2.0 换成 pt）；也可提供「约 N 个汉字宽」语法糖（`N * 当前字号`，方块近似） |
| 吃到行尾 | 从当前位置铺到本行剩余宽 `W_remain` |

**属性**

| 属性 | 约定 |
| --- | --- |
| 宽度 | 定宽与吃到行尾互斥；长度走 §2.0 |
| 线粗 / 线色 | 走长度与颜色模块；线色默认跟当前文字色或黑 |
| 相对基线偏移 | 线在基线略下方，避免切字 |
| 线上叠字 | **第一版不做** |

**断行与错误**

- 定宽 blank 视为不可拆占位；宽于当前行 `W` → `UnbreakableWiderThanFrame`（不拆、不裁）
- 吃到行尾的 blank **后面禁止再有 run**（组装期报错）
- blank 不进字形测量；绘制度一条水平 `Stroke`；不增加行高
- 跨页随所在行走

与块级「分隔线」的边界：填空可与左右文字同一段；分隔线是独立流块，通常通栏宽。

#### 2.3 分隔线（已定方向）

块级流节点，对外是 `Block::HLine`（`HLineSpec`）。它画在当前框内，用来做标题下线、落款前分隔、附件前分隔。它不是行内填空，也不是 `behind` 上的 `LayerMark`。

| 项 | 约定 |
| --- | --- |
| 默认宽度 | 当前框满宽 `W`（规则同 §2.1） |
| 定长短于 `W` | 允许；对齐默认 **Center**（也可 Start / End） |
| 线粗 / 线色 | §2.0 长度与颜色；默认实线 |
| 虚线 / 双线 / 竖线 | **第一版不做** |
| `space_before` / `space_after` | 线上下空白，计入节点高度 |
| 占位高 | `space_before + thickness + space_after` |
| 分页 | **整条不可拆**，放不下则整节点去下一页 |
| 绘制 | `Fragment` 内一条水平 `Stroke`；列内只画到列宽 |

与填空边界：分隔线是独立块、通常通栏；填空在段落行内、可与左右文字相邻。

#### 2.4 stack（已定方向）

把若干流块从上到下排成一组。文档根上依次追加的正文是**隐式 stack**（调用方不必写 `stack`）。

**与 `columns` 互相嵌套。** `stack` 与 `columns` 可以**反复包裹对方**，不限制层数（仍受文档限额约束）：

| 组合 | 效果 |
| --- | --- |
| stack 里套 columns | 竖排到某处后出现并排栏 |
| columns 某一列里再套 stack | 该列内继续往下堆段落、表、线… |
| columns 里再套 columns | 栏内再分栏 |
| stack 里再套 stack / keep_together | 局部绑组 |

靠嵌套组合复杂版式，不另发明布局节点种类。换行宽按 §2.1：进入某一列后子树 `W` = 列宽；回到外层 stack 后恢复外层框宽。内部为可递归的 `FlowNode` 树（`Stack` 孩子可含 `Columns`，每列内是 `Stack` 或等价列表）。

**对外 API**

| 项 | 约定 |
| --- | --- |
| 样式作用域 | `Block::Styled`。`TextStyle` 里的字号和颜色作用于 `children`，到这组孩子结束为止。不另做无样式分组节点。要整组留在同一页，用 `keep_together` |
| 整组尽量同一页 | 对外 **`keep_together`**；内部可为 `KeepTogether(Vec<FlowNode>)` |
| 组级 margin | **第一版不做** |
| 组高超过一页正文框 | **报错**（`UnsplittableTallerThanFrame`），不静默拆开 |
| 与跨页总原则 | 见 §2.5.1：默认可跨页；要粘页时用 `keep_together`，不要靠「不给 columns/段落跨页」 |

`Stack::split` / 段后距与 KeepTogether 自然高规则按设计稿：孩子序放置；段后距放不下则丢掉；KeepTogether 自然高含孩子之间 spacing，不含组外最后一段 spacing。

#### 2.5 columns（已定方向）

流内从左到右分栏；每列内部是竖直内容（stack），可与 stack **反复互嵌**（§2.4）。不是整页报纸式 snaking 分栏。

| 项 | 约定 |
| --- | --- |
| 列宽 | `Fixed` / `Ratio` / 至多一列 `Auto`（Auto 吃剩余，不按内容收缩） |
| `column_gap` | 列间距，走 §2.0；默认 **12 pt** |
| 列竖向对齐 | **顶对齐** |
| 栏间竖线 | **第一版不做** |
| 列内可放 | 段落、线、嵌套 stack/columns、keep_together；表等随各元素再认 |
| 栏内 `page_break` | **禁止**。列内分页在组装时失败，错误是 `InvalidCellContent` |
| 跨页 | **允许**（见下「跨页总原则」）；各列在本页剩余高上切分，head 画本页、tail 作为下一页的 columns |

#### 2.5.1 跨页总原则（已定方向）

| 项 | 约定 |
| --- | --- |
| 默认 | **流式元素默认可以跨页**（段落按行、columns 按列内切分、表按行等，细则随元素） |
| 例外 | 某些原子块**整块不可拆**：如图片、`svg`（以及日后同类「整物件」）；放不下则整块去下一页，若高于整页正文框则报错 |
| 不要跨页时 | 用 **`keep_together`** 包住（不必再发明一套「Stack + keep 属性」对外 API；内部可以是 KeepTogether 包一层孩子列表） |
| 组高超过一页 | `keep_together` 仍报错，不静默拆开 |

即：跨页是默认能力；「整组粘在一页」是显式 opt-in（`keep_together`），不是每个元素各自一个 `unbreakable` 开关（元素自身若天然不可拆，如图片，则本身就是例外）。

#### 2.6 table（已定方向）

块级表：行列、列宽、边框；表宽默认吃满当前框 `W`（§2.1）。`columns` 的某一列里**可以**放 table；**表的单元格内禁止**再放 `columns`（避免格内套栏）。嵌套表是否允许另定；先按禁止嵌套表实现，除非以后放开。

**跨页**

| 项 | 约定 |
| --- | --- |
| 跨页 | **允许**；切分单位是**整行**（含因合并而横跨的逻辑行规则见下），不在行中横切 |
| 续页表头 | **可开关**；**默认开启**：有表头时续页先画表头再画剩余正文行 |
| 关开关时 | 续页只续正文行，不再画表头 |
| 防死循环 | 开启重复时，表头总高 + 一行正文高 > 整页正文框 → 报错 |

整表粘在一页：外包 `keep_together`。

**表头**

| 项 | 约定 |
| --- | --- |
| 多行表头 | **要**：开头连续若干行是表头（`header` 可多次或一次声明多行） |
| 重复范围 | 开关打开时，续页重复**全部表头行**（不只第一行） |

**列宽与外观**

| 项 | 约定 |
| --- | --- |
| 列宽 | `Fixed` / `Ratio` / 至多一列 `Auto`（Auto 吃剩余）；长度 §2.0 |
| `cell_padding` / 边框 | 有；边框宽 0 表示不描边 |
| 格内内容宽 | `列宽 - 2*padding - 边框占位`；格内段落按此断行 |

**合并单元格**

| 项 | 约定 |
| --- | --- |
| `colSpan` / `rowSpan` | **要** |
| 约束 | 合并区域不重叠、不越出表边界；非法合并组装或 lower 时报错 |
| 与跨页 | 一行（物理绘制行）仍不从中间拆。若某逻辑行因 `rowSpan` 与后续行绑在一起，跨页策略需保证：**跨页缝不能切在某个尚未结束的 rowSpan 中间**——该合并块放不下则整块（所涉行）去下一页；若合并块高于整页正文框则报错 |
| 与表头 | 表头区域内合并允许；表头与正文之间不建议跨区合并（禁止表头行 rowspan 伸进正文），避免续页重复表头时几何错乱 |

**单元格孩子**

| 允许（随元素落地逐步放开） | 禁止 |
| --- | --- |
| 段落（含填空）、分隔线、spacer；图片/列表随对应 PR | **`columns`**、pageBreak、keep_together |
| | **嵌套 table**（先禁止） |

表是 `TableSpec`。`header` 是表头行，`body` 是正文行。单元格用 `col_span` 和 `row_span` 合并。`repeat_header` 默认 `true`。

#### 2.7 image（已定方向）

流内位图块，类型是 `ImageSpec`。与 `LayerMark::Image`（页面坐标）分路。两边共享解码和绘制，分页行为不同。

**跨页。** 整块不可拆（§2.5.1）。剩余高度不够 → 整张去下一页；高于整页正文框，或显示宽大于当前框 `W` → 报错，**不自动缩小**。

**输入来源**

| 来源 | 约定 |
| --- | --- |
| 原始字节 + 格式（PNG / JPEG / GIF / WebP） | **主路径**；GIF/WebP 只取第一帧作静止图 |
| Base64 | 不作为排版核心类型；可选薄解码助手，或调用方解码后传字节 |
| `http(s)` URL | **不做**（已确认） |
| 本地路径 / Data URI 主路径 | **不做**；调用方读文件或剥 Data URI 后传字节 |

**尺寸（长度 §2.0 → pt）**

| 调用方给出 | 结果 |
| --- | --- |
| 宽且高 | 用给定值（不强制保持像素比） |
| 只给一边 | 另一边按像素宽高比（需解码） |
| 两边都不给 | `1 px = 1 pt` |

**其它**

| 项 | 约定 |
| --- | --- |
| `fit` / `cover` | **第一版不做** |
| 在框内对齐 | 默认 **Start**；可 Center / End |
| 格内 | **允许**（随图片能力落地） |
| 具名 images 字典 | **不做**（2026-10-19；原延后） |
| 图上链接 | 随 §8；不阻挡本元素 |

layout 只持 `ImageId` 与 pt 矩形；解码与 krilla 句柄在 backend。`interpolate` 固定 `false`。

#### 2.8 列表 ul / ol（已定方向）

块级列表；项可跨页（§2.5.1）。标记只出现在该项**首页**片段；续页不重复标记，但正文仍保持与有标记时相同的左缩进。

**ol 编号**

| 项 | 约定 |
| --- | --- |
| 样式 | **枚举**覆盖常用：十进制 `1/2/3…`、大写字母 `A/B/C…`、小写 `a/b/c…`、罗马数字（大写/小写各一档，如 `I/II/III`、`i/ii/iii`） |
| 中文「一、二、三」等 | **不**塞进上述枚举。调用方按项设置 `ListItemSpec.marker` 字符串，用于「一、」「（一）」 |
| `start` | 枚举样式下的起始序号，默认 1（字母/罗马从对应起始值换算） |
| 倒序、多级自动 `1.1.1` | **第一版不做**（嵌套是各层各自一套标记 + 缩进，不是自动大纲编号） |

自定义标记字符串时：该项不再用枚举算法生成；宽度仍参与 `marker_width` 测量，过宽则报错。

**换行与悬挂缩进（已定）。** 项内正文可用宽为 `W_parent - indent`，**续行不得顶回编号下方**：

```text
1. 第一行文字……到行末
   第二行继续……        ← 左缘与第一行文字左缘对齐，不伸进标记列
```

即标记占独立列；正文列左缘 = 外框左 + 本层缩进（含标记列宽）。所有正文行（含换行后的行）都从正文列左缘起排。

**嵌套缩进（已定）。** 列表可嵌套；每深一层增加一级缩进（再扣一个 `marker_width` 或统一 `nest_indent`，具体数值可配置，默认与 `marker_width` 联动）。内层的 `W` 更窄，换行规则同上，不超出本层编号列。

**其它**

| 项 | 约定 |
| --- | --- |
| ul | 默认标记 `•`（U+2022）；亦可按项自定义字符串 |
| `marker_width` | 标记列宽；须 `> 0` 且小于当前内容宽；标记 advance 更大则报错，不裁剪 |
| 项内 | 段落（含填空）、线、spacer、嵌套列表；**不要** table/columns（第一版） |
| 格内列表 | 允许（随列表落地） |

#### 2.9 pageBreak（已定方向）

流里的**强制换页**标记，不是可见内容。分页器特殊处理，**不走**普通 `split`。单元格 / 列表项内 **禁止**（`InvalidCellContent`）。

**三态游标（不用布尔）。**

| 状态 | 含义 |
| --- | --- |
| `Fresh` | 尚未开出正文页 |
| `HasBody` | 当前页已有正文 |
| `PendingBlank` | 刚因 pageBreak 结束上一页，下一页挂起未提交 |

| 行为 | 结果 |
| --- | --- |
| 文档开头的 pageBreak | **no-op** |
| 有内容后一个 pageBreak | 结束当前页；挂起页在流结束时若仍空则**丢掉**（不因此多一页） |
| 有内容后连续两个 pageBreak | 中间提交一页**空白正文**（仍画页眉页脚、计入页数），再挂起 |
| 流结束且 `PendingBlank` | 丢掉挂起页 |

即：`内容 + break + 内容` → 两页内容；`内容 + break + break + 内容` → 内容、空白、内容。

**属性**

| 项 | 约定 |
| --- | --- |
| 奇偶页 break（pdfmake 有） | **第一版不做**；只要「在这里换页」 |
| before/after 两种挂法 | 换页是流里的 `Block::PageBreak`。它在序列中的位置就是断开点。不另做段落属性 `pageBreak: after`。以后若做属性，语义仍映射到这个游标 |

与 `keep_together`：一个防拆、一个强制断；可组合（组后再 break）。

#### 2.10 header / footer（已定）

页眉是 `SectionSpec.header`，页脚是 `SectionSpec.footer`，类型都是 `Option<BandSpec>`。`None` 表示这一侧不画。`BandSpec` 只描述带里画什么。它不改变带高，也不改正文流。

**带高 = 上下 margin。**  
header / footer **不再另设高度**。页眉带高 = `margin.top`，页脚带高 = `margin.bottom`。正文框高 = 页高 − top − bottom。正文宽 = 页宽 − left − right。带高来自 margin，**不由**装饰内容撑开。带内装不下（行盒高于带高，或按约定超出可用宽）则**报错**。不裁切，不加高，不回流正文。

**水平。**  
页眉和页脚默认横跨整页宽，从 `x = 0` 到页宽。`BandInset::Fixed` 设置左右缩进。默认两边都是 0，所以带仍是整页宽。`BandInset::PageMargins` 改用当前页的左右 margin，使带内文字与正文左右对齐。正文流仍遵守四边 margin。

**槽位。**  
`left` 和 `right` 各是 `Option<BandSlot>`。`None` 表示这一侧空白。`BandSlot::Text` 是 `TextRun` 的序列。`TextRun::Literal` 是固定文字。`PageNumber` 与 `PageCount` 是全文页码和全文页数。`SectionNumber` 与 `SectionCount` 是本节页码和本节页数。库在绘制该页时填入这些数。页码从 1 起。带高不依赖填入后的字符串。`BandSlot::Link` 的写法见 §8。

```text
y=0 .. margin.top               页眉带（高=margin.top；横可全页宽）
y=margin.top .. page_h-mb       正文框（左右缩进 margin.l/r）
y=page_h-mb .. page_h           页脚带（高=margin.bottom；横可全页宽）
```

#### 2.11 section（已定方向）

**版式段**，不是物理页。一份 PDF 可含多个 section（合订多篇公文）；每个 section 内仍是流式正文，可自然换页、可 `pageBreak`。

| 项 | 约定 |
| --- | --- |
| 名字 | 对外是 `SectionSpec`。不用 `page`，以免与物理页混淆 |
| 遇新 section | **强制从新物理页开始**（即使上一 section 末页未满） |
| 文档默认纸张 | `DocumentSpec.page_size`（含方向）。section 未覆盖则用文档默认 |
| section 覆盖 | `SectionSpec.page_size` **优先于**文档默认 |
| 纸张尺寸 | **枚举**常用规格（至少含 A 系列如 A3/A4/A5 等，具体清单实现时列全）+ **Custom(宽, 高)**（长度 §2.0 → pt） |
| 方向 | **枚举**横向 / 竖向，**只与尺寸枚举搭配**：`Orientation + SizeEnum` → **最终**页宽高（例如 A4 竖 = 210×297 mm 对应 pt，A4 横则宽高对调）。**Custom 已是最终尺寸**，不再套方向 |
| margin / header / footer | 写在该 `SectionSpec` 上。页眉和页脚画在这一节生效的 margin 带里 |

**页码。** `TextRun` 提供两套，都从 1 起。见 §2.10 的槽位。

| 变体 | 含义 |
| --- | --- |
| `PageNumber` / `PageCount` | 整份 PDF 的物理页序号与总数 |
| `SectionNumber` / `SectionCount` | 本 section 从本段第一页起算的序号与段内总页数 |

调用方把这些变体和 `TextRun::Literal` 排成需要的句子，例如「总第 x 页」，或「本篇第 y 页，共 z 页」。库在分页完成后填数。

只有一个 section 时，`DocumentSpec.sections` 里放一个 `SectionSpec`。`DocumentSpec::new` 一开始就是这一节。此时全文页码与 section 内页码相同。

#### 2.12 behind / front（已定）

`SectionSpec.behind` 和 `SectionSpec.front` 是 `LayerMark` 列表。它们不进正文流，不占正文高度。`behind` 做水印。`front` 做电子章。坐标相对**当前物理页**左上，y 向下。横纵都不因左右 margin 自动缩进，与页眉默认全宽一致。要对齐正文区域，调用方用该节的 margin 和页宽、页高自己计算坐标。

**作用域。** 标记写在 `SectionSpec` 上。只有一节时就写在那一节上。每一物理页绘制时，库用 `PageWhen` 选择页面。`PageWhen::All` 是本节每一页。`PageWhen::Last` 是全文最后一页，也就是全文页码等于全文页数。本节页码可以写进 `TextRun`。`PageWhen` 只有这两档。

**叠层顺序（每页）：**  
`behind` → `header` → 正文 → `footer` → `front`  
（水印在最底，页眉压水印，章在最上。）

**标记种类。**  
- `LayerMark::Text` 与 `LayerMark::Image`。图源同 §2.7。顶层 Text / Image **不旋转**。  
- path 用 `LayerMark::Line`、`Rect`、`Ellipse`，以及 stroke 和 fill。水印斜线、装订线、页上任意框走这里。不另设绝对定位 canvas 节点。  
- **旋转组（2026-10-19 确认）。** `LayerMark::Rotated { when, degrees, pivot, shapes }`。`degrees` 为顺时针角度（度）。`pivot` 与 `shapes` 内坐标均为**旋转前**的页坐标。`LayerShape` 为 `LayerShape<K>`，变体是 `Line` / `Rect` / `Ellipse` / `Text` / `Image`。`Text` 与 `Image` 字段分别对齐顶层 `LayerMark::Text` / `Image`（无 `when`，跟组走）；文字 `at` 仍是行盒左上。path、Text、Image 可在同一组内混排，按 `shapes` 列表顺序绘制。`shapes` 为空则静默忽略。非有限 `degrees` 失败（现有 `NonFiniteRotation`）。不做嵌套 `Rotated`。斜向叠字水印走 `behind` + `Rotated` + `LayerShape::Text`；半透明仍走颜色 opacity。居中由调用方自行估算字宽/字高并偏移 `at`；库不提供测宽辅助。此变更使 `LayerShape` 带类型参数 `K`，属 0.x breaking。  
- 半透明走颜色的 opacity。  
- 逃逸层不做流式断行。  

**不做（本条）。** 章随签署栏流走仍搁置，见 §1。不另设平行的 watermark API。

#### 2.13 spacer（已定）

流内**竖直空白**块，不画可见内容。高度为 §2.0 **非负长度**（类型层约束，可为 0）。

| 项 | 约定 |
| --- | --- |
| 与段后距 | 不同：段后距放不下则丢；spacer 是独立节点 |
| 跨页 | **可拆**：本页能吃多少吃多少，余量作为更矮的 spacer 去下一页（可成为下页唯一起始内容） |
| 格内 | **允许** |
| 色块背景 | **不做** |

#### 2.14 流内 canvas（不做）

跟着正文流走、**占正文高度**的矢量块。与 §2.12 逃逸不是同一 API。2026-10-19 由延后收成**不做**：流内横线用分隔线；页坐标矢量用 `LayerMark` path；复杂图走 §2.7 `image` 或外部生成。

| 项 | 约定 |
| --- | --- |
| 第一版及以后 | **不做**。逃逸绘制用 §2.12 的 `LayerMark` path 变体 |

分隔线覆盖高频横线；复杂示意图由调用方生成后走 §2.7 `image`。

#### 2.15 qr（不做独立元素）

不设一等公民 `qr` 节点，也不在库内集成二维码生成器。调用方自行生成后走 **§2.7 image**（或日后 svg）贴进流或 `front`/`behind`。与「传图」相比，单独 qr 元素只是薄糖衣，意义不足。

#### 2.16 svg（不做独立元素）

不设 svg 节点，库内不做 SVG 解析。需要图走 **§2.7 image**；需要简单页坐标矢量走 **§2.12 behind/front path**。与否决 qr 同一原则：传图已能覆盖则不设平行元素。

#### 2.17 toc（不做）

不设目录节点，不做 `tocItem` 收集与页码回填。非本项目公文/函证刚需；需要时由调用方自排段落或表。内链跳转与书签见 §12.4，仍不做 toc。

### 3. 文字（已定）

**范围。** 第一版就承诺**横排中文 + 拉丁文**。函件/公文几乎都是中文；不做中文则本项目无意义。实现可按 PR 先加 ASCII 测试再加汉字夹具，但产品与 rustdoc **不**写成「仅英文」。

**断行。** 原子是扩展字素簇；用小分类表（BK/SP/ID/AL/OP/CL/Other），中文（ID）字间可断，西文词（AL）内部不断；**不是**完整 UAX #14。细则采纳设计稿决策表（句号不落行首、开口括号粘后字、行首普通空格丢掉等）。

**明确不做：** kerning、连字、bidi、阿文/印度系 shaping、竖排、ruby。对齐是 Start/Center/End/Justify（无 bidi 时 Start=左）；Justify 见 §12.3。

**管线：** charmap → advance（skrifa）→ 断行 → 同一批 glyph 再画；不调用 krilla `draw_text`。缺字见 §4。

### 4.1 字体键与注册（已定，2026-10-14）

三包都不内置生产字体。字体由调用方以**字节**传入，不收文件系统路径。测试夹具字体不进 git；测例靠环境变量（`PDFCRAFT_PDF_FONT` / `PDFCRAFT_CJK_FONT` / `PDFCRAFT_FORMS_FONT` / `PDFCRAFT_ORGCHART_FONT`），未设置则跳过。

**`pdfcraft-pdf` 公共形状（已定）。**

- 调用方定义自己的键类型 `K`（例如 `enum DocFont { Cjk, Latin }`），要求 `Copy + Eq + Hash`。正文与样式只引用 `K`，**禁止** `font: String` / `&str` 这类裸字符串名。换字体只改注册处。
- 库提供值类型：`FontFace`（`bytes` + 面 `index`）、`FontFamily`（四槽见 §12.1）、`FontRegistry<K>`。
- `FontFace.bytes` 是 `Arc<Vec<u8>>`。`pdfcraft-orgchart` 的 `FontBytes.data` 也是 `Arc<Vec<u8>>`。调用方可以把同一份 `Arc` 交给多份文档。`FontFace::new` 与 `FontBytes::new` 包住调用方拥有的字节。`FontFace::from_shared` 与 `FontBytes::from_shared` 原样保存已有的 `Arc`。调用方键 `K` 不变。forms 与 orgchart 仍是单次字体。forms 的 `FontBytes` 仍是借用 `&[u8]`。
- `Resources::with_fonts(FontRegistry<K>)`（或等价构造）。`DocumentSpec` / `ParagraphSpec` / `InlineRun` 等需要选字体的规格类型带上 `K`。
- 未 `register` 的键 → 结构化错误，整份失败。
- 库**不**要求调用方 `impl` 某个 Font trait。业务自己 `enum` + 组装 `FontRegistry` 即可（组数据，不是实现行为）。与 §1「调用方给值、不写闭包、不实现库内 trait」一致。

**中英混排。** 调用方仍可用**显式 run**：不同 `InlineRun` 标不同的 `K`。调用方调用 `InlineRun::split_latin` 时，库按 §12.2 的字符表把一段字符串切成多个 run，并为拉丁类和其他字符各指定一个键。不调用该函数时，库不按字符拆字体。每个 run 只在自己的键上查字，缺字仍是 `MissingGlyph`，不去另一个键再找。

**`pdfcraft-forms` / `pdfcraft-orgchart`。** 继续单次 `FontBytes`（或等价）即可，不必上 `FontRegistry`。禁止 forms ↔ pdf 互相依赖。

### 10. `pdfcraft-forms` 填写已有 AcroForm（已定）

本条于 2026-10-12 确认。`pdfcraft-forms` 读取带 AcroForm 的第三方 PDF 字节，按字段值在控件矩形上绘制，并返回 PDF 字节。它不生成表单模板。它不进入 `pdfcraft-pdf` 的排版管线。

**字节进出。** `list_fields` 与 `fill_and_flatten` 只接受 PDF 字节。`fill_and_flatten` 在成功时返回 PDF 字节。公共 API 以字节为输入。PDF 与字体都不接收文件系统路径。

```rust
pub fn list_fields(pdf: &[u8]) -> Result<Vec<FieldInfo>, Error>;

pub fn fill_and_flatten(
    pdf: &[u8],
    fields: &HashMap<String, FieldValue>,
    options: &FillOptions,
) -> Result<Vec<u8>, Error>;
```

`fields` 的键是 widget 的名字。名字来自 `/T`。名字、`/FT`、`/Ff`、`/Opt` 和 `/AP` 各自沿 `/Parent` 取第一个已经存在的键。库不拼接点分全名。库跳过缺少 `/T` 或 `/Rect` 的注释。

**每次成功调用都 flatten。** 字段表为空时也 flatten。库把墨迹画在页面内容之上，然后去掉全部 Widget 注释，并去掉 catalog 里的 `/AcroForm`。库不写字段 `/V`，也不写外观流。库不保留未绘制控件的原外观。页面上预先印好的内容保留。

**可填的类型。** Text、CheckBox、ListBox、ComboBox。加密的 PDF 失败。AcroForm 上存在 `/XFA` 键时失败。空的 `/XFA` 数组也失败。把 Signature、RadioButton 或 PushButton 放进 `fields` 则失败。Signature、RadioButton 和 PushButton 没有放进 `fields` 时，flatten 会把它们和其它未填控件一起剥掉。

**硬失败。** 需要画文本或选项字符串时，必须提供带 `glyf` 的 TrueType 字节。未提供字体，或字体损坏，则失败。cmap 缺字时整份失败。库不输出降级 PDF。库不内置 CJK 回退字体。文字缩到最小字号后仍超出控件框时，整份失败。

v1 默认从 12 pt 起画，每次减小 0.5 pt，最小 7 pt。行高是字号的 1.2 倍。框内边距为左 1 pt、右 1 pt、底 1 pt、顶 0.5 pt。码位大于 U+007F 的文字可以按字符断开。ASCII 先按词断开，超宽的词再按字符断开。显式换行用来分段。最小字号下单个字形仍宽过框，则为 `BoxOverflow`。文字和勾选都 clip 到 widget 的 `/Rect`。

**同名 widget。** 同一个名字的多个 widget 使用同一个 `FieldValue`。类型检查和 `/Opt` 检查以遍历到的第一个同名 widget 为准。

**坐标。** 控件矩形使用 PDF 用户空间。原点在左下，y 向上。文本默认左对齐、底对齐。这些矩形不进入 `pdfcraft-pdf` 的画布坐标。`pdfcraft-pdf` 画布仍是左上原点，y 向下。

**公共形状。** 类型是 `FieldInfo`、`FieldValue`、`FillOptions`、`Error`、`ErrorKind`。

`list_fields` 为每个 widget 返回一条 `FieldInfo`。公开字段是 `name`、`field_type`、`page_index`、`options`。公开的 `FieldInfo` 不含矩形，也不含 checkbox 的 on-state。`field_type` 可以是 Text、CheckBox、ListBox、ComboBox、Signature、RadioButton、PushButton。`list_fields` 可以返回 Signature、RadioButton 和 PushButton。返回这三种类型只表示 PDF 里有这些控件。`fill_and_flatten` 拒绝填写这三种类型。ListBox 与 ComboBox 的 `options` 是合法值列表。其它类型的 `options` 为 `None`。

`FieldValue` 只有 `Text(String)` 与 `CheckBox(bool)`。ListBox 与 ComboBox 使用 `FieldValue::Text`。该字符串必须落在展平后的 `/Opt` 中。导出值与显示值都算合法。画出来的是调用方给出的字符串，不改写成显示值。`CheckBox(true)` 在矩形内画勾，clip 到该 `/Rect`。勾的形状对标 ZapfDingbats 字符 `4`，短边为字号的 0.7 倍，并居中。`CheckBox(false)` 不画勾。其它 `FieldValue` 变体配到 checkbox 上则失败。

`FillOptions.font` 是当次调用的字体字节。类型是 `FontBytes { bytes, index }`。`index` 是 TTF 或 TTC 的面索引。不设 process-global 默认字体。公共 API 没有 `set_default_font`。v1 没有 fill 锁。以后只有在证明各次调用必须共享一块可变字体状态时，才可以加锁。

`font_size` 默认 12 pt。调用方可以按字段名覆盖起始字号（`font_size_overrides`）。`missing` 默认 `Error`。未知字段名失败，覆盖表里的未知名同样失败。设为 `Ignore` 时，调用跳过未知名字。水平对齐默认左对齐。垂直对齐默认底对齐。调用方可以按字段名覆盖这两种对齐。竖直位置按该行字形墨迹，不是 OS/2 的 ascent/descent。末行只剩一个字形时，允许再降最多 2 pt 以换更少的行。

`line_below` 把字段名映射到框底下方的偏移，单位是 pt。库在那里画一条与框同宽的黑线，线宽 1 pt。这条线不需要字体。`absolute_lines` 是 PDF 用户空间里的绝对线段。它不参与字段名检查。页号越界时，叠绘失败。

**错误。** `Error` 是结构体，含 `kind: ErrorKind`，并可以带 `source`。`pdfcraft-pdf` 的 `Error` 同样用 `kind` 区分失败。`Error` 与 `ErrorKind` 定义在 `pdfcraft-forms` 里，不使用 `pdfcraft_pdf::Error`。本 crate 不提供 HTTP 用的 `to_dict`。字段类错误带字段名。确认的 `ErrorKind` 如下。

| Kind | 何时 |
| --- | --- |
| `NotAPdf` | 无法当 PDF 打开 |
| `Encrypted` | 加密输入 |
| `HasXfa` | AcroForm 含 `/XFA` |
| `UnknownField` | 未知字段名 |
| `IllegalChoice` | 值不在 `/Opt` |
| `InvalidCheckbox` | checkbox 的值类型非法 |
| `InvalidArgument` | 非正字号，或其它非法参数 |
| `MissingGlyph` | 缺字 |
| `BoxOverflow` | 最小字号仍超出控件框 |
| `FontNotConfigured` | 需要字体但未提供，或字体损坏 |
| `SignatureNotWritable` | 试图填写 Signature |
| `WidgetUnsupported` | 试图填写 RadioButton 或 PushButton |
| `FlattenFailed` | 叠绘合并或写出失败 |

**依赖。** 版本钉在 workspace 的 `[workspace.dependencies]`。`lopdf` 钉 `=0.45.0`，并且 `default-features = false`。它负责读结构、叠绘和剥离。0.45 把解析器编进库，不再提供 `nom_parser` feature。不要打开 `default`，因为那会启用 `chrono-clock` 和 `rayon`。不要打开 `font_embedding`，因为那会再依赖一份 `skrifa`。`skrifa` 钉 `=0.48.0`，负责量宽和 cmap，与 `pdfcraft-pdf` 相同。`pdfcraft-forms` 不依赖 `pdfcraft-pdf` 这个包。`pdfcraft-forms` 不依赖 `krilla`。`pdfcraft-forms` 与 `pdfcraft-pdf` 互相没有依赖边。`pdfcraft-pdf` 仍然不引入 `lopdf`。本 crate 版本是 `0.1.0`，可以发布。TrueType `glyf` 子集已按 [`pdfcraft-forms-font-subset-spec.md`](pdfcraft-forms-font-subset-spec.md) 实现，不增加依赖。成功路径保留原 glyph id。OTF 仍未做，缺字仍然失败。同一份输入调用两次 `fill_and_flatten`，输出字节相同。实现清零嵌入字体里的时间戳，避免字节随调用时间变化。

**本条只确认产品范围。** 本条不改 `crates/pdfcraft-forms` 的源码。后来的变更写入了 ASCII 文本、勾选、选项、始终 flatten、对齐与按字段覆盖、`font_size_overrides`、`line_below`、`absolute_lines`，以及把 TTC 拆成单个面再嵌入。中文填写的折行已在；夹具字体不入库，测例在设置 `PDFCRAFT_FORMS_FONT` 时跑。成功路径嵌入保留原 glyph id 的 TrueType `glyf` 子集。OTF 仍未做。

### 11. `pdfcraft-post` 后处理已有 PDF（已定）

本条于 2026-10-14 确认。产品合同草稿见 [`pdfcraft-post-spec.md`](pdfcraft-post-spec.md)。`pdfcraft-post` 对**已有 PDF 字节**做后处理：写 `/Info`、加密、合并多份 PDF，并把步骤收成 `Pipeline`。输入输出都是内存中的 PDF 字节。它不是 `pdfcraft-pdf` 的排版管线，也不服务某一 Web 项目。

**与 `DocumentSpec.info` 分开。** 排版生成走 `DocumentSpec.info`：Creator 固定为 `pdfcraft`，不开放 Producer。后处理走 `SetMetadata`：Creator 与 Producer **可写**。二者是不同产品，不要混用一套字段策略。

**加密。** AES-256，Standard Security Handler revision 6（lopdf `EncryptionVersion::V5`）。调用方必须提供加密配置与密码。库不在内部替调用方随机生成 owner 密码。空 user 密码打开是合法场景。

**合并。** `parts` 为空失败。仅一份返回原字节。多份按列表顺序拼接页面。默认不保留大纲；`preserve_outlines=true` 时尽量保留第一份的大纲。不保留附件与结构树。

**错误。** `Error` + `ErrorKind`，骨架对齐 `pdfcraft-forms`（及 `pdfcraft-pdf` 的同类形状）。不提供 HTTP / `to_dict`。

**依赖。** workspace `lopdf =0.45.0`（`default-features = false`）。不依赖 `pdfcraft-pdf`、`pdfcraft-forms`、`pdfcraft-orgchart`；反向同样禁止。不引入 `krilla`（本栈无水印绘制）。版本 `0.2.0`，可以发布。

**本栈明确不做或延后。**

- Watermark（斜向叠字）：**延后**。
- 输入限额（`configure_limits` / `max_bytes` / `max_pages` 或进程全局限额）：**延后**。
- HTTP / `to_dict` / AppError 映射。
- Web finalize 编排（自动生成 owner 密码、`exported_at` 写入 keywords、落库、脱敏 payload）。
- 库内「未传密码则自动生成」。
- 把加密、合并、后处理写 Info 做进 `pdfcraft-pdf` 的 feature。

**硬规则。** 实现只在本仓库。禁止修改 hcsw 工程（含 `/mnt/data/dev/hcsw-pdfcraft`）里的任何文件；只读对照行为允许。

**`pdfcraft-pdf` 仍不做的事（本条不改变）。**

- 加密生成中的文档。
- 合并第三方 PDF。
- 在 `pdfcraft-pdf` 内提供后处理 `/Info` 改写 API。

### 12. `pdfcraft-pdf` 排版补项（已定）

本条于 2026-10-16 确认。四项各一个 PR，顺序是 §12.1 → §12.2 → §12.3 → §12.4。§12.1 先定 `InlineRun` 与 `FontFamily` 的形状，后两项建在它上面。同日讨论过、仍搁置的：电子章跟签署栏流走（见 §1）、某页关 header/footer（见 §5）。`LayerMark` 文字/图片旋转做斜向水印已于 2026-10-19 确认，见 §2.12。

#### 12.1 行内样式

**形状。** 正文文字只有一种 run：`InlineRun::Text { text, font, style: RunStyle }`。`InlineRun::Bold` 删除。`RunStyle` 字段是粗体、斜体、下划线、删除线、字距、颜色、字号。字段都可不设，不设即继承外层。`RunStyle` 取代 `TextStyle`：`Block::Styled`、`BandSlot`、`LayerMark::Text` 用同一个类型。

**斜体。** 只用真斜体面。字面组有 `regular`，可选 `bold`、`italic`、`bold_italic`。run 要的面在所用字面组里没有，整份失败。粗体用 `BoldFaceRequired`，斜体与粗斜体各有对应错误。不做倾斜变换伪斜体，不用别的面顶替。

**下划线与删除线。** 位置取该 run 自己家族的常规面：下划线读 `post`，删除线读 `OS/2`，按该 run 的字号缩放。粗细固定为 1pt。同一行内连续、同字号、同颜色的装饰段画成一条线，位置取第一段，中英文交界处不跳高低。线色等于文字颜色。行中空格和 §12.3 拉开的间隙也画线。行尾丢掉的空格不画。`Blank` 自带线，不受装饰影响。

**字距。** 单位 pt，可以为负。加在本行相邻两个字素簇之间，行末不加。字距参与测量与断行。某个字形 advance 加字距小于 0，整份失败。

#### 12.2 显式拉丁拆分与行盒

**拆分。** 库不按字符自动拆字体。调用方调用 `InlineRun::split_latin(text, cjk, latin)` 时，库按本节字符表把 `text` 切成多个 `InlineRun::Text`。`cjk` 是不归拉丁类的字所用的键，不限于汉字。`latin` 是拉丁类所用的键。每个 run 的 `style` 是 `RunStyle::default()`。空字符串得到空 `Vec`。连续分到同一个键的字符合并成一个 run。两个键相等时，整段是一个 run。函数不查 `FontRegistry`，不读字体，不报缺字。缺字仍在 `layout_spec` 里按该 run 的键报 `MissingGlyph`，不去另一个键再找。函数不生成 `InlineRun::Link` 或 `Blank`。页眉、页脚、单元格短文本、图层文字、矢量块文字、列表编号和圆点不调用这个函数。列表编号和圆点仍只用注册顺序里的第一个字体文件。

**字符表。** 切分单位是扩展字素簇。簇的归类看第一个标量，簇内其余标量跟着走。第一个标量属于拉丁类时，整簇用 `latin`。拉丁类是 U+0020 空格、U+0021 至 U+007E，以及下列块里 `char::is_alphabetic` 为真的字符。Latin-1 Supplement（U+00C0–U+00FF）的字母，即 À–Ö、Ø–ö、ø–ÿ。Latin Extended-A（U+0100–U+017F）。Latin Extended-B（U+0180–U+024F）。Latin Extended Additional（U+1E00–U+1EFF）。Latin Extended-C（U+2C60–U+2C7F）。Latin Extended-D（U+A720–U+A7FF）。Latin Extended-E（U+AB30–U+AB6F）。

其余标量整簇用 `cjk`。包括汉字、假名、谚文、全角数字、全角拉丁字母、弯引号（U+2018、U+2019、U+201C、U+201D）、破折号（U+2013、U+2014）、省略号（U+2026）、Latin-1 里的非字母、IPA 扩展（U+0250–U+02AF）、修饰字母（U+02B0–U+02FF）、换行（U+000A、U+000D）。换行留在它分到的那个 run 的字符串里。`"A\nB"` 得到 `"A"`（`latin`）、`"\n"`（`cjk`）、`"B"`（`latin`）。`"A\r\nB"` 里的 CR+LF 是一个簇，第一个标量不是拉丁类，整簇用 `cjk`，字符串仍是调用方写入的 `\r\n`。`e` 加 U+0301 是一个簇，用 `latin`。`合同金额 USD 100` 里 `"合同金额"` 用 `cjk`，`" USD 100"` 用 `latin`。弯引号围住的 `ABC` 分成三个 run，引号用 `cjk`，字母用 `latin`。

**粗体与斜体。** `split_latin` 不读取、不设置粗体或斜体。§12.1 保持不变。一个 run 的 `style.bold` 与 `style.italic` 只在这一个 `font` 键的 `FontFamily` 里选择 `bold`、`italic` 或 `bold_italic`。中文键的粗体文件和拉丁键的粗体文件没有配对。返回的 run 是 `bold: None`、`italic: None`。外层 `Block::Styled` 打开粗体时，这些 run 按 §12.1 继承，然后各自用自己的键选文件。

**行盒。** 同一行画到多个字体文件时，每个文件按它在该行上的字号缩放。行盒取这些文件里最大的上伸部、最深的下伸部、最大的行距。自然行高是上伸部减下伸部加行距。自然行高再与该行最大字号乘以段落行高因子比较，取较大值。基线放在最大上伸部处。字号不按另一个文件的 em 框缩放。这一行没有字形、只有 `Blank`，但本段还有文字 run 时，用第一个文字 run 解析之后的字体文件，含该 run 自己的粗体或斜体，字号用段落字号。整段没有任何文字 run、只有 `Blank` 时，不读字体。行高等于段落字号乘以行高因子。基线在行盒顶部向下一个段落字号处。

**不做。** 不改 `FontFamily` 的四槽，不加拉丁组字段。不在页眉、页脚、单元格、图层、矢量块、列表标记里自动拆分。不做 §12.3，不做 §12.4。

#### 12.3 两端对齐

`Alignment::Justify`。断行不变，只在摆放字形时分余量。

- 第一阶段：分给本行空格，每个空格最多加宽 0.5em（取该空格所在 run 的字号）。
- 第二阶段：余下的平均分给相邻两个字素簇之间的间隙。这两个字素簇里至少要有一个是汉字或全角标点。汉字和紧挨着的拉丁字母之间也算。英文词内部不拉开。
- 以下几种行照 Start 摆放：段落最后一行、硬换行前的行、带 `Blank::Fill` 的行、没有可分间隙的行。
- 行尾丢掉的空格和首行缩进不参与分配。分余量在加完 §12.1 字距之后。
- 链接矩形与装饰线按拉开后的位置算。
- 不做标点挤压。

#### 12.4 文内跳转与书签

**锚点。** 用包裹块 `Block::Anchor { id: String, outline: Option<OutlineEntry>, child }`，正文内任何能放 `Block` 的位置都可用。跳转目标是 `child` 第一个片段所在页，目标点取这个片段的左上角，写成 XYZ 目标，不改变阅读器的缩放比例。锚点在重复表头里出现多次时，取第一次出现的位置。`child` 不产生片段时失败。不做行内锚点。不做按页码跳转。

**链接。** `InlineRun::Link { target: LinkTarget, runs }`。`LinkTarget` 是 `Uri(String)` 或 `Anchor(String)`。§8 的 URI 规则不变。`BandSlot::Link` 只保留 URI。

**书签。** `OutlineEntry { title, level }`，书签树按文档顺序生成。第一项层级须为 1，之后每项最多比前一项深一级，标题非空，否则失败。没有任何 `outline` 时不写书签树。

**校验。** id 为空、重复，或链接指向不存在的 id，都使 `layout_spec` 失败，错误带 `Location`。没被链接引用的锚点允许存在。

**依赖。** krilla 0.8.2 已有 XYZ 目标、链接目标和书签树，`pdfcraft-pdf` 不新增依赖。`pdfcraft-post` 的 `merge_pdfs` 不改。
